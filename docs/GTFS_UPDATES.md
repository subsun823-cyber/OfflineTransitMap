# バス時刻表の自動更新

## 実装済みの動作

- WorkManager 2.12.0で約24時間ごとに確認。アプリを閉じてもAndroidが実行を管理し、端末再起動後も継続します。実行時刻は通信・電池・省電力設定・OS制限で遅れます。強制停止中の実行は保証しません。
- 設定→「時刻表の更新」で自動更新ON/OFF、Wi-Fi等の従量制でない接続への限定、手動確認、事業者別URL、最終確認・期限切れ・結果を表示。初期値は自動ON／従量制でない接続のみ。手動確認にも通信・電池・空き容量の条件を適用します。
- `ETag`／`Last-Modified`が使える配布元には条件付きGETを送り、304なら再変換しません。対応しない配布元ではZIPを取得してSHA-256で変更を判定します。
- ZIPからUTF-8 CSVを読み、既存v5形式の更新用SQLite DBを作成します。PythonはAndroidで実行できないため読込処理だけKotlinに追加し、スキーマと既存`KeioDatabase.merge`による事業者単位の統合を共用します。
- **バックグラウンドでは取得・検証・適用予約まで**行います。利用中のDBハンドル、検索結果、ナビの便番号を壊さないよう、**次回の画面起動でDBを開く前に自動適用**します。開始前のダイヤは開始日以降の起動まで待機します。予約済み更新の適用に通信は不要です。
- 更新は既存DBのコピーへ統合し、検証後に原子的に差し替えます。JR・他社・地図を更新対象へ含めません。更新が失敗すれば従来データを残します。
- 有効期限は`feed_info`／calendar／calendar_datesから取得し、運行日を勝手に延長しません。配布元も期限切れ、現在より終了日の古い配布、破損ZIP、別会社、不正な参照・時刻・重複などは適用しません。
- 更新済みデータを次回起動で古いAPK同梱データへ戻さないようDB内の更新マーカーを使用。DBを削除して再準備した場合は、残ったHTTPキャッシュ情報をリセットします。

## まだ必要な配布元情報

**恒久的に最新版GTFS ZIPを取得できる元URLが未提供のため、既定URLは未設定です。実サーバーからの定期取得はまだ有効化できていません。**

前回のGigaFileは期限付きの受領リンクであり更新元には使いません。ユーザーへ、西東京バス・京王バスを取得した元のURL／データ一覧ページを質問済みです。

配布担当者が `app/src/main/assets/bootstrap/bus-updates.json` に次の2項目を設定すれば、各端末で同じURLが初期設定になります。

- `ntbus`: 元の本体DBの `NT_` に対応する **西東京バス・コミュニティバスを含む同じ全件GTFS**。部分路線のZIPを指定すると対象全体を置き換えるため、必ず配布範囲を確認してください。
- `keio-bus`: `GTFS_KEIO_BUS:` に対応する京王バスの全件GTFS。

URLはファイル本体を返すHTTPSです。閲覧HTML、ログインページ、特定日版だけのURL、期限付き署名URLは継続更新元に適しません。認証キーが必要な提供元の場合は公開Gitへキーを保存せず、取得方法を別途確認してください。端末の設定で上書きしたURLはAPK内の既定値より優先します。

設定を完了するまでは、同梱・保存済みの時刻表を利用します。今回のコードだけで西東京バスの実配布元と接続済みとは扱わないでください。

## 対応範囲と制限

- 現在対象は西東京バス等と京王バス。JR／京王電鉄ODPT・地図の更新は対象外です。
- 日本時間の通常バスGTFSを対象とします。親停留所、かな翻訳、のりば、運行例外、24〜47時台、乗降不可を扱います。頻度指定、予約制乗降、空の中間時刻、乗継運賃等の未対応形式は安全側に停止します。
- 経由ゾーンによる運賃は該当路線で非表示。路線・発着ゾーン指定／均一運賃は変換し、競合する料金を推測しません。shapesによる道路形状・道路ナビは追加していません。
- ZIP上限64MiB、読み取る展開内容上限768MiB、便50万、停車時刻500万等の上限があります。失敗時は定期実行時に再確認し、Worker内の再試行は最大3回です。部分ダウンロードの再開は未対応です。
- 有効期間の異なる複数世代を同時に検索する機能はありません。新ダイヤが未来の日付で公開された場合は開始日まで旧ダイヤを使い、次回起動時に置き換えます。

## 検証

- JVMでCSV・GTFS・日付判断・HTTPS/304/転送保護・キャンセルを検証。
- 提供済み京王バスZIPを実際のKotlin取込処理に通し、ホストSQLiteへ投入。Python版で検証済みの停留所・路線・便・時刻・運行日・運賃と一致することを確認。
- 実DBの西東京バス部分を再統合し、JR／京王電鉄／京王バスの不変性・重複防止・参照整合性を検証。
- Androidの起動時適用・未来ダイヤ待機・破損時保護・同梱版への逆戻り防止テストはコンパイルまで。Android実機でのWorkManager実行・通信断・再起動・更新後UIは未確認です。

実データを含むJVM検証の例（開発環境のパスに置き換える）:

```sh
OFFLINE_TRANSIT_GTFS_FIXTURE=/path/to/keio-bus-gtfs.zip \
  bash gradlew :app:testDebugUnitTest :app:compileDebugAndroidTestKotlin :app:assembleDebug
python3 tools/check_apk_data.py
```

環境変数未指定時は実GTFS追加テストのみスキップします。通常の合成データテストは実行されます。

参考: [Android WorkManager](https://developer.android.com/topic/libraries/architecture/workmanager)、[GTFS仕様](https://github.com/google/transit/blob/master/gtfs/spec/en/reference.md)。
